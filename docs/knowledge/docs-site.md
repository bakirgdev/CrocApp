# Docs site

Operational knowledge for `web/docs/` (Docusaurus 3.10.2, pnpm 12, TypeScript 7).

## Local development

```bash
pnpm --dir web/docs start
```

`start` runs the `tokens` script first (`cp ../../design/tokens.css src/css/tokens.css`), then `docusaurus start`. `tokens.css` is gitignored, same pattern as `web/landing/tokens.css`: edit `design/tokens.css`, never `web/docs/src/css/tokens.css` directly, the copy is overwritten on every `start` or `build`.

The same `tokens` script copies `web/landing/assets/img/mascot-web.webp` to `static/img/mascot.webp` (gitignored), the navbar logo. It is the one web derivative of the mascot (`design/brand.md` → Mascot); never commit a second copy.

To build the full Pages artifact (both surfaces, what CI publishes) locally:

```bash
scripts/assemble-site.sh          # writes ./_site/, landing at /, docs at /docs/
```

## Content and styling rules

- Page copy is bound by `design/content.md` (terminology, capitalization, the approved security claims) and `design/brand.md`. Headings and sidebar titles are sentence case; app controls are quoted in bold, Title Case, exactly as the app spells them.
- Theme styling lives in `web/docs/src/css/custom.css`, mapped onto `design/tokens.css` with no literals (`design/web.md` → Docs site). The code theme is `src/prismTheme.ts`, the same token mapping. The navbar collapses at Docusaurus's own 996px breakpoint, not ours, so do not set `display` on a `.navbar__item` outside a `min-width: 997px` media query.
- Screenshots come from `scripts/capture-screenshots.sh --copy-web` and go in as a light and dark pair on one line, each with a `#gh-light-mode-only` or `#gh-dark-mode-only` fragment (`custom.css` shows the one that matches the theme toggle). Docusaurus rewrites the paths to hashed ones, so the phone-width cap in `custom.css` keys off the alt text: an iPhone shot's alt must say "on iOS".

## Adding a page

New file under `web/docs/content/` (not `docs/`, that name is taken by the repository's own contributor docs). Frontmatter needs `title`, `description`, and `sidebar_position`. The sidebar is autogenerated from the directory tree, so nothing is ever added to `sidebars.ts`: order comes from `sidebar_position`, and a new directory needs a `_category_.json`. `routeBasePath: '/'`, so `content/guide/foo.md` serves at `/docs/guide/foo/`.

The docs site is English only: `docusaurus.config.ts` configures the single locale `en`.

## Cutting a version

No second version exists. `current` is labelled `1.0` in `docusaurus.config.ts` (`versions.current.label`) and no `versioned_docs/` exists. When a later release changes behavior that the old version's readers still need described, run `pnpm --dir web/docs run docusaurus docs:version 1.0` first, then relabel `current` for the new release. `web/docs/package.json` carries the release version (`1.0.0`). Until a second version exists, the navbar's `docsVersionDropdown` renders nothing. Docusaurus hides it below two versions, so this is not a misconfiguration.

## Broken links fail the build

`onBrokenLinks`, `onBrokenAnchors`, `markdown.hooks.onBrokenMarkdownLinks`, and `markdown.hooks.onBrokenMarkdownImages` are all `throw`. A bad internal link or anchor fails `pnpm run build`, which fails `scripts/assemble-site.sh`, which fails `github-pages.yml`. `github-pages.yml` runs the same assembly on `pull_request` (build only, no deploy), so a broken link is caught before merge.

## One workflow publishes both surfaces

`github-pages.yml` calls `scripts/assemble-site.sh` and uploads the whole `_site/`. Editing only `web/docs/**` still rebuilds the Docusaurus site and re-copies `web/landing/` verbatim, and editing only `web/landing/**` does the reverse. GitHub Pages replaces the entire artifact on every deploy, so a single workflow always ships both. The workflow triggers on `web/landing/**`, `web/docs/**`, `design/tokens.css`, `scripts/assemble-site.sh` and its own file.

## What `assemble-site.sh` asserts

The script fails the build unless the landing files and the receive-link page are in place. The list is in `landing-page.md`, "How it ships". It also requires `index.html` under the `docs` folder.

## Traps

- **Frontmatter values containing a colon must be quoted.** `description: Fixes for X: stalled transfers` breaks the build with "bad indentation of a mapping entry". Quote the whole value: `description: "Fixes for X: stalled transfers"`. Several pages under `content/` already need this, check before adding a colon to any frontmatter field.
- **`showLastUpdateTime` renders nothing for a file that is not yet committed.** It reads git history per file (`fetch-depth: 0` in `github-pages.yml` makes this work in CI); a new page with only uncommitted local edits shows no "last updated" line until it lands in a commit. This is not a bug, only confusing while drafting.
