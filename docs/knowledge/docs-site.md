# Docs site

Operational knowledge for `web/docs/` (Docusaurus 3.10.2, pnpm 12, TypeScript 7).

## Local development

```bash
pnpm --dir web/docs start
```

`start` runs the `tokens` script first (`cp ../../design/tokens.css src/css/tokens.css`), then `docusaurus start`. `tokens.css` is gitignored, same pattern as `web/landing/tokens.css`: edit `design/tokens.css`, never `web/docs/src/css/tokens.css` directly, the copy is overwritten on every `start` or `build`.

To build the full Pages artifact (both surfaces, what CI publishes) locally:

```bash
scripts/assemble-site.sh          # writes ./_site/, landing at /, docs at /docs/
```

## Adding a page

New file under `web/docs/content/` (not `docs/`, that name is taken by the repository's own contributor docs). Frontmatter needs `title`, `description`, and `sidebar_position`. The sidebar is autogenerated from the directory tree, so nothing is ever added to `sidebars.ts`: order comes from `sidebar_position`, and a new directory needs a `_category_.json`. `routeBasePath: '/'`, so `content/guide/foo.md` serves at `/docs/guide/foo/`.

The docs site is English only. The `bs`, `de`, `es`, `fr` and `ru` drafts were removed for 1.0 (#11); git history keeps them.

## Cutting a version

Not needed yet, current *is* 0.9.9, no `versioned_docs/` exists. When 1.0.0 tags: `pnpm --dir web/docs run docusaurus docs:version 0.9.9`. Until a second version exists, the navbar's `docsVersionDropdown` renders nothing, that is Docusaurus hiding it below two versions, not a misconfiguration.

## Broken links fail the build

`onBrokenLinks`, `onBrokenAnchors`, `markdown.hooks.onBrokenMarkdownLinks`, and `markdown.hooks.onBrokenMarkdownImages` are all `throw`. A bad internal link or anchor fails `pnpm run build`, which fails `scripts/assemble-site.sh`, which fails `github-pages.yml`. `github-pages.yml` runs the same assembly on `pull_request` (build only, no deploy), so this is caught before merge, not only after a push to `main`.

## One workflow publishes both surfaces

`github-pages.yml` calls `scripts/assemble-site.sh` and uploads the whole `_site/`. Editing only `web/docs/**` still rebuilds the Docusaurus site *and* re-copies `web/landing/` verbatim, and editing only `web/landing/**` triggers the reverse — GitHub Pages replaces the entire artifact on every deploy, so a single workflow always ships both.

## What `assemble-site.sh` asserts

After copying both surfaces it fails the build unless `index.html`, `404.html`, `.well-known/security.txt`, `.well-known/apple-app-site-association` (listing both app IDs) and `docs/index.html` exist. It also checks the link page `web/landing/r/index.html` (R23): it must exist, set `<meta name="referrer" content="no-referrer">` (the code lives in the URL fragment), and load no remote `script`, `link`, `img` or `iframe`. Keep that page free of third-party resources; the one network hop it offers is a user-clicked link to getcroc.com.

## Traps

- **Frontmatter values containing a colon must be quoted.** `description: Fixes for X: stalled transfers` breaks the build with "bad indentation of a mapping entry". Quote the whole value: `description: "Fixes for X: stalled transfers"`. Several pages under `content/` already need this, check before adding a colon to any frontmatter field.
- **`showLastUpdateTime` renders nothing for a file that is not yet committed.** It reads git history per file (`fetch-depth: 0` in both Pages workflows makes this work in CI); a new page with only uncommitted local edits shows no "last updated" line until it lands in a commit. Not a bug, just confusing while drafting.
