Why CrocApp

Three common ways to move a file between devices each stop working in a different situation.

AirDrop

It works Apple to Apple, and you both need to be in the same room.

LAN tools

It works on the same Wi-Fi only. Guest networks and client isolation break it silently.

Cloud drops

You upload your file to a company first, then send a link. They have the file.

CrocApp

Use a code phrase, in the same room or on different continents. The relay only ever sees ciphertext.

How it works

Three steps. Nothing to sign up for.

  1. 1

    Choose what to send

    Files, a whole folder, or a snippet of text.

  2. 2

    Read out the code phrase

    CrocApp shows something like cape-junky-widow. Say it, message it, or show the QR code.

  3. 3

    Enter it on the other device

    They see what is coming and accept it. The transfer starts.

What happens underneath

The code phrase authenticates both devices through PAKE, a password-authenticated key exchange.

Transfers are end-to-end encrypted.

The relay only ever sees ciphertext.

When the two devices connect over the local network, the data stays on that network.

  • Auto-accept off by default, and marked when on

Questions

What does it cost?

Nothing. No purchase, no subscription, no advertising, and no analytics.

What does the encryption cover?

Transfers are end-to-end encrypted, the code phrase authenticates both devices, and the relay only ever sees ciphertext. That is croc's design rather than anything CrocApp adds.

CrocApp has not had a formal third-party security audit. The code is open if you want to look.

Do I need an account?

No. There is nothing to sign up for.

Does my file go through a relay?

Usually yes. A relay forwards traffic between two devices that cannot reach each other directly, and it only ever sees ciphertext. Send as Link is the exception: files are encrypted on your device before they reach the link server (getcroc.com, or the one you choose), and the key travels in the link's # fragment, which browsers never send to a server. The link server holds the encrypted file until the link expires. You can point CrocApp at your own relay instead.

What if we are on the same Wi-Fi?

When the two devices connect over the local network, the data stays on that network. CrocApp tries both paths at once and uses whichever connects first.

Does it work with the croc command line tool?

Yes, in both directions. CrocApp embeds croc's own library, so a phrase from the CLI works in the app and a phrase from the app works in the CLI.

Windows, Linux, Android?

Not from CrocApp, which is an Apple-platform app. Use the croc CLI, which runs everywhere, or one of the other croc clients, listed under Inspirations in the docs. They all speak the same protocol.

Can I run my own relay?

Yes. Point CrocApp at any croc relay, with a password and IPv6 if you want them. Running croc relay on a machine you control is enough.

Contribute

It is MIT licensed and the whole thing is in the open. Bug reports are as useful as patches.

Most useful right now: try it on a network that breaks other tools, and say what happened. Guest Wi-Fi, captive portals, corporate VPNs and client isolation are exactly the conditions this app exists for, and exactly the ones hardest to test alone.

After that: accessibility testing with VoiceOver and larger text, translations once the copy settles, and anything in the issue tracker marked help wanted.
